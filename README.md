# 智感云联 V3.0 · 智慧大棚监控后端

ESP32 采集环境数据 → 云端中转 → 本服务判定告警 → 网页大屏与手机远程控制。

这是一个**真实部署过、被真实故障打过脸**的物联网后端。仓库里 43 个测试全部离线可跑，不需要硬件、不需要联网、不需要密钥。

> 项目的价值不在"我实现了几个接口"，而在于**每一条告警规则都被反向验证过**：它会误报吗？误报时人会怎么误解？——下面第五节列了三个真实的误判，以及怎么定位和修掉的。

---

## 一、跑一下

**双击 `start.bat`**，回车（默认演示模式），浏览器自动打开 `http://127.0.0.1:5000/ui/`。

启动器会自己找 Python、装依赖、清掉占用 5000 端口的旧实例、在两个独立窗口里起服务。

手动跑也行（两个终端）：

```
python app.py                     # 终端 1：后端
python fake_device.py normal      # 终端 2：假数据源
```

跑测试：

```
python -m pytest -q               # 43 passed，约 0.8 秒
```

**不需要 `config.json` 也能跑。** 巴法云私钥不进版本库，本地演示模式下完全不碰它。

## 二、能演示什么

`fake_device.py` 提供三个剧本，用来验证不同分支：

| 剧本 | 命令 | 现象 |
|---|---|---|
| 正常 | `fake_device.py normal` | 四项数值缓慢波动，无告警 |
| 劣化 | `fake_device.py drift` | 约 56 秒先报 `SOIL_DRY`，61 秒叠加 `HUMI_LOW` |
| 掉线 | 直接关掉数据源窗口 | 30 秒后 `online:false`，页面置灰并显示「链路中断」 |

还有第四个：`drill_low_water.py`，每 0.5 秒把水位压到 5%，用来稳定复现**无水禁泵**（否则假数据源每 2 秒推一次 72%，你点开泵的那一刻读到的还是 72%，永远撞不上 409）。

**掉线时四个数值不会归零。** 保留最后一次读数，并标注「最后一条数据在 xx 秒前」。归零会让人以为棚里 0℃，实际只是设备失联——把「没数据」显示成「数据是 0」，是监控系统最常见也最危险的错误。

## 三、架构

```
ESP32 + DHT11/土壤/水位
        │  MQTT 上报
        ▼
   巴法云（MQTT broker）
        │  HTTP 拉取 / 下发
        ▼
  ┌─────────────────────────────────────┐
  │ app.py        ingest / latest / cmd │
  │   ├── rules.py     业务判定（纯函数）│
  │   ├── bemfa.py     云端通道          │
  │   └── compat.py    前端兼容层        │
  └─────────────────────────────────────┘
        │  同源静态托管
        ▼
  frontend/  大屏 + 手机控制页
```

两个设计选择值得说明：

**`rules.py` 是纯函数，不 import 任何 IO。** 所以判定逻辑能脱离硬件、脱离网络、脱离时钟测试——43 个用例里有 28 个测的就是它，全部毫秒级。

**前端由 Flask 同源托管**（`/ui/`），而不是另起静态服务器。这样彻底消除了 CORS，手机上输一个地址就能用。

## 四、接口

原生接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/ingest` | 设备上报。必填 `dev`、`temp`、`humi`，可选 `soil`、`water_level`、`voltage`、`pump_on` |
| GET | `/api/latest` | 最新一条 + 实时算出的 `online` 与 `fault` |
| GET | `/api/history?minutes=60` | 历史序列，按时间升序 |
| POST | `/api/cmd` | `{"pump":"on","duration":30}`。水位低于 15% 时返回 **409 拒绝** |

前端兼容接口（统一信封 `{"code":0,"msg":"","data":{...}}`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/sensor/current` | 毫秒时间戳；超 5 秒无新数据返回 503，带上最后一条与近 60 帧 |
| GET | `/api/device/shadow` | 设备影子 `{power, ts, source}` |
| POST | `/api/device/pump` | `{cmdId, action, durationSec}`，被拒时 409 + 中文原因 |

**503 的载荷里带 `stale` / `age_sec` / `last`。** 前端据此显示「最后一条数据在 18 秒前」，而不是把接口失败渲染成一片 0。

## 五、三个真实误判（这部分是重点）

### 1. 水位从 72% 掉到 5%，系统报「止回阀失效」

复现步骤：灌一帧低水位数据，泵是停的，后端返回两条故障：

```
fault: ['WATER_LOW', 'CHECK_VALVE_FAIL']
```

`CHECK_VALVE_FAIL` 的判据是「泵没转但水位在降」——两帧一减，掉了 67 个百分点，看起来完全符合。但真漏水不可能两秒漏掉 67%。

**反向后果更要命**：给水箱补水，15% 跳到 72%，它同样会报一次止回阀失效。用户每次正常补水都会被吓一次。

修法是给趋势判定加一道跳变闸门：窗口内相邻两帧变化超过 15 个百分点，这段序列不下任何趋势结论。补了 3 个回归用例。

> 教训：**趋势类规则必须能区分「连续变化」和「数据跳变」。** 物理量按秒连续变化，传感器故障和人工操作导致的才是跳变。

### 2. 堵塞规则在泵启动 2 秒就报错

原判据是「泵在转，10 秒窗口内水位没降」。但泵启动后头几秒水位本来就不会动——水还在管子里往前推。

修法是加 `min_span_sec=10` 最短观察期：观察时长不够就返回空列表，先不下结论。用例从「2 秒后报警」改成「10 秒后才报警」。

> 教训：**判断"没有变化"时，必须同时问"观察了多久"。** 没有时间跨度的"没变化"是无意义的。

### 3. 数据源断开，接口返回 0.0

老版本 `except` 分支里写了 `return 0.0`。断网、平台宕机、密钥过期、报文格式错——四种完全不同的故障，全部伪装成同一个「0℃ 正常读数」。

前端拿到 0.0，把它当真实数据画进曲线，页面上显示「当前温度 0℃」，用户以为棚里冻死了。

修法是改成 503 + `valid:false` + 最后一条有效读数 + `age_sec`，并在 `ingest` 里加量程校验（-40~80℃、0~100%RH），超量程的帧直接标为无效、不写历史。

> 教训：**异常不能降级成合法的正常值。** 用哨兵值（0、-1、空字符串）代表失败，是产生"看起来一切正常"这类事故的标准配方。

## 六、七条业务规则

`rules.py` 全部实现，`tests/` 全部覆盖：

| 规则 | 判据 | 动作 |
|---|---|---|
| 无水禁泵 | 水位 < 15% | 拒绝开泵，返回 409 |
| 堵塞 | 泵在转，观察够 10 秒，水位不降 | 报 `PUMP_BLOCKED` |
| 回流 | 泵未转，水位持续下降 | 报 `CHECK_VALVE_FAIL` |
| 传感器失效 | 读数超出物理量程 | 报 `SENSOR_INVALID`，不参与业务判定 |
| 掉线 | 超 30 秒无数据 | `online:false`，故障列表只留 `OFFLINE` |
| 低压 | 电池 < 10.5V | 报 `LOW_VOLTAGE`，同时禁泵 |
| 执行板失联 | 串口连续 5 帧校验失败 | **未实现**，依赖 #1↔#2 的串口心跳协议 |

**掉线时故障列表只保留 `OFFLINE`。** 早期版本是 `[HUMI_LOW, SOIL_DRY, OFFLINE]` 三条并列——设备都失联了，还在报它的湿度，等于让用户去修一个可能根本不存在的问题。

**禁泵是拒绝，不是告警。** 早期版本水位 5% 也照发指令，只在小程序上弹个红字。水泵空转几分钟就能烧，这类保护必须是硬拒绝（409），不能靠前端自觉。

## 七、为什么 bat 里没有中文

这是踩出来的，记下来免得以后有人"顺手优化"回去。

`.bat` 里写中文，在中文 Windows 上会随机崩，报错长得像代码 bug：

```
'efined' 不是内部或外部命令
'10)' 不是内部或外部命令
'?ESP32' 不是内部或外部命令
```

两个原因叠加：

1. **cmd 按系统代码页（936）逐字节解析 bat 文件。** UTF-8 中文是 3 字节，被按 GBK 解成 1.5 个字符，多出来的半个字节会把后面那个 ASCII 字符吞掉。`defined` 少了 `d` 就是这么来的。
2. **行尾必须是 CRLF。** 纯 LF 时跨行的 `(...)` 块会崩，报一堆莫名其妙的括号错误。

`chcp 65001` 写在第一行也救不了——它的生效时机在 cmd 已经开始读文件之后。

所以现在：**bat 纯 ASCII + CRLF，所有中文和逻辑在 `launcher.py` 里。** Python 的输出编码可控（读控制台代码页，936 就输出 GBK），不会出这种事。

## 九、已知限制

- 数据存内存（`deque(maxlen=500)`），重启即清空。换 SQLite 只需改 `_save` / `_all` / `_last` 三个函数。
- 单设备。多设备需要给历史记录按 `dev` 分桶。
- 光照传感器未接入，`light` 返回 `null`，大屏显示「未接入」而不是 `0 lx`。
- `water_level` 使用百分比。真实水位计若输出厘米，需在 `ingest` 里换算。
- 执行板失联未实现，依赖串口心跳协议，固件尚未编写。
- 巴法云主题名只能使用字母和数字，且同一 clientId 同时只能有一个连接。因此后端下发指令走 HTTP 而非 MQTT——用 MQTT 会和设备抢连接，把 ESP32 踢下线。
